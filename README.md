# Путевые заметки

Приложение для ведения дневника путешествий: поездки, путешественники и
заметки по дням. Консольная версия (ПР3) дополнена веб-интерфейсом на
Django (ПР5).

## Назначение

Позволяет хранить поездки, вести заметки по дням и не терять их между
запусками программы.

## Целевая аудитория

Путешественники, которые ведут дневник поездок.

## Предметная область

Основные объекты: поездка, путешественник, заметка.

Путешественник делает заметки о днях поездки. На один день поездки
может быть только одна активная заметка. Архивная заметка не блокирует
день: на него можно создать новую заметку. Заметку можно создать только
на день, который входит в период поездки.

## Основные сущности

### Trip — поездка
Атрибуты: `id`, `title`, `country`, `start_date`, `end_date`.
Методы и свойства: `duration_days` (свойство), `lasts_at_least()`,
`includes_day()`, `validate_dates()` (`@staticmethod`), `from_data()`
(`@classmethod`), `to_data()`, `__str__()`.

### Traveler — путешественник
Атрибуты: `id`, `name`, `email`.
Методы: `from_data()` (`@classmethod`), `to_data()`, `__str__()`.

### Note — заметка
Атрибуты: `id`, `trip` (объект `Trip`), `note_date`, `traveler`
(объект `Traveler`), `text`, `is_archived`.
Методы: `archive()`, `to_data()`, `__str__()`.

## Взаимодействие объектов

`Note` хранит ссылки на объекты `Trip` и `Traveler`, а не их
идентификаторы: `note.trip.title`, `note.traveler.name`. В JSON
сохраняются только идентификаторы `trip_id` и `traveler_id`; при
загрузке `storage.py` восстанавливает ссылки на объекты.

Архивирование не удаляет объект из коллекции, а вызывает
`note.archive()`.

## Основные операции

- поездки: добавление, поиск по названию, проверка длительности,
  отбор по длительности, сортировка, вывод списка;
- путешественники: добавление, поиск по имени или e-mail, вывод списка;
- заметки: проверка свободного дня, создание, архивирование, вывод.

## Хранение данных

JSON-файлы в каталоге `data/`: `trips.json`, `travelers.json`,
`notes.json`. При загрузке данные превращаются в объекты, при
сохранении — обратно в данные JSON.

## Веб-интерфейс (ПР5)

Используется Django 5.2, Bootstrap 5.3 (через CDN), HTML.

| URL | Страница | View-функция |
|-----|----------|--------------|
| `/` | главная, навигация | `homepage.views.index()` |
| `/trips/` | список поездок | `trips.views.trips()` |
| `/trips/<int:trip_id>/` | страница поездки | `trips.views.trip_detail()` |
| `/notes/` | список заметок | `notes.views.notes()` |
| `/notes/<int:note_id>/` | страница заметки | `notes.views.note_detail()` |

Если поездка или заметка не найдены, возвращается страница с кодом 404.
Для несуществующих адресов подключён `handler404`
(`homepage.views.page_not_found`).

Общий HTML-каркас страниц формирует функция `page()` из
`homepage/views.py`. Это временное решение: на следующей работе HTML
переедет в шаблоны Django.

View-функции используют классы и функции ПР3: `load_trips()`,
`load_travelers()`, `load_notes()`, `find_trip_by_id()`,
`find_note_by_id()`, `is_day_free()`. Консольное приложение
(`python main.py`) продолжает работать.

На этом этапе данные хранятся в JSON, Django ORM, база данных и формы
не используются.

## Запуск приложения

Веб-версия (Django):

```text
python manage.py migrate
python manage.py runserver
```

Адрес: http://127.0.0.1:8000/

Консольная версия (сохранена):

```text
python main.py
```

## Тестирование

```text
pytest -v
python manage.py test
```

`pytest` проверяет объектную модель и хранилище (каталог `tests/`),
`manage.py test` — веб-страницы (файлы `tests.py` приложений).

Тесты проверяют создание объектов, их методы, связь заметки с поездкой
и путешественником, правило «одна активная заметка на день» и
сохранение в JSON.
